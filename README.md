# Tasks — Android

Download [Tasks 0.40.0](https://github.com/swettgm/task-list-android/raw/refs/heads/main/downloads/Tasks-v0.40.0.apk). Install over the existing app to retain your tasks and settings.

A personal Android checklist based on the supplied task list. The app includes the original task definitions and saved history, works offline, and keeps existing installed data when updated.

- Settings → Changelog shows the full published update history, newest first. Historical releases can be expanded individually. Widget task actions and the header provide light haptics, respecting the phone’s touch-feedback setting. Text buttons, dropdowns and editable fields are left-aligned; control contents are vertically centered and icon controls retain their centered layout.
- Hold the date to open Projects without adding a third tab. Projects are notes with an optional date and duration, no labels, time or checkboxes. Tap a project to edit, complete, reopen or delete it; the outline trash icon turns red on the first tap, resets to gray after three seconds, and deletes on a second tap within that window. Projects have their own plus and completed list. Make task copies the idea into one unset task and archives the project, retaining its notes. Project data stays separate from task progress and widgets.
- Tap a widget task title to open the exact app editor as a rounded home-screen overlay. Save updates the shared task definition and widget immediately; daily edits carry forward. Cancel, Back, and tapping outside close it without saving, and the keyboard stays closed until a text field is tapped. Widget checkboxes and Today / In progress badges keep their separate actions.
- Opens on Today, with a date-only header and corner plus for Quick add. Only Quick add opens the keyboard automatically. Detailed task creation and editing focus the dialog and collapse the keyboard until a text field is tapped. Their action buttons stay visible in a reserved footer while the fields scroll above it. Existing tasks have an outline trash button: the first tap turns it red without adding text, confirmation expires after three seconds, and a second tap deletes the definition from current and future lists. Input changes reset confirmation; stored completion history remains intact. Tap outside either task editor to dismiss it without saving.
- Task checkboxes use the chosen accent color, centered vertically against task titles, including wrapped titles and checklist steps. Mobile text autosizing is disabled. Drag horizontally between Today and Upcoming: both panels follow the finger and settle on release, with short drags returning to the starting tab. reduced-motion settings skip the animation. Tab taps switch immediately; vertical scrolling and taps on interactive controls retain their usual behavior. Horizontal drags can start on task controls, including time, repeat, labels, checkboxes and the gear, without activating their tap actions. Both screens share task-row markup, fonts and spacing; duration and other details sit below the title. Duration and repeat frequency stay side by side, with time wrapping separately when needed. Subtask Do now buttons share the visible outline of parent task controls. Only the checkbox changes completion; titles, checklist titles and labels do not. Tap a label emoji to edit the task’s labels, or tap the displayed time, repeat frequency or duration for a focused popup that preserves the rest of the task. Inline shortcuts suppress blue touch highlights and text selection; keyboard focus stays visible with a neutral outline. Completion saves immediately, pauses for two seconds for undo, then hides the task without an extra undo note. Urgent badges are red and sit beside the task title when space permits, using the same spacing and vertical centering as In progress. Each badge moves below the title only when it cannot fit, without squeezing the title. The top summary shows the completion fraction and remaining duration in hours and minutes, with no redundant pending count; untimed tasks are shown separately. New tasks default to unset priority with no selected level. Detailed editors offer only High, Medium and Low. Show completed opens the completed list with today’s completions highlighted first; the button has no count.
- Guild has a static image label extracted from frame zero of the supplied v8 GIF, with transparent corners. The crest is slightly larger than the standard emoji glyphs, about 24% larger than its original display size, in task rows, choices, the selected filter, native pickers and the widget summary. The existing Guild task gains the label while retaining its other edits and contexts. The image is also available in the label icon picker.
- Contexts use emojis: 🏠 🚗 📱 💻 🌳. Choose existing contexts on tasks; add custom contexts and choose their emoji in Settings. Use a palette or an emoji from your keyboard. Changing a label emoji updates existing tasks, the filter and native widget/quick-add pickers while retaining the label identity.
- Use the native time picker and Tomorrow / Weekend shortcuts alongside the date picker. Weekend selects Friday, including the current weekend’s Friday on Saturday or Sunday. Edit duration with larger, full-width Hours and Minutes boxes. Notes and Checklist stay expanded on separate rows. Lists show durations without numbering or the word total.
- Labels and normal edits are saved to a task definition and carry forward to its future daily recurrences. Checklist changes apply from the edited occurrence onward; completion is stored per occurrence.
- Repeat with Every X days, weeks, months, or years, or choose Daily, Weekdays, or Weekends. Clean out truck shows Sunday–Thursday.
- Upcoming includes each future daily occurrence even when the task is pending on Today; other work currently pending on Today stays excluded. Tomorrow is expanded with a Tomorrow plus ordinal date heading; later dates show their full weekday name plus ordinal date, in separate frameless dropdowns without divider lines. Upcoming tasks have checkboxes, visible Do now state and a Do today button with a left-facing arrow. Do today moves only the selected occurrence, preserves its completion identity and repeating definition, removes it from Upcoming and updates Today and the widget.
- Add, rename, reorder or remove checklist steps in Edit task. Stable step identities preserve checkmarks and completion dates; occurrences before the edit retain their original checklist.
- Android 12 and newer can enable precise reminders through Settings → Allow precise reminders. Exact alarms are used when permitted, with an inexact fallback if permission is unavailable or revoked. Returning to the app refreshes the plan. Previously armed reminders that Android has delayed survive unrelated saves for up to 24 hours; completion, Notify off, or a time/date/frequency change cancels the obsolete reminder.
- Set a task time and check Notify beside Urgent for a scheduled notification. Settings has a separate daily reminder, initially 9 AM, and independent controls for both reminder types. Android notification permission is required. Alarms resume after restart and app updates; power-saving mode or force-stop can delay/block delivery.
- Saves check commit results and reject unreadable state rather than resetting it. Local storage cannot guarantee against uninstalling, clearing data or device loss.
- Upcoming sections use month/day ordinals such as Nov 4th, including tomorrow. The next day stays expanded.
- Weekend tasks become available in Today starting Friday at 6 PM, adjustable through Settings → Weekend starts Friday. Saturday/Sunday one-offs and weekends-only repeats keep their original completion identities. Daily tasks keep their normal schedule; Friday visibility does not opt tasks into notifications.
- Subtask summaries use a centered disclosure arrow, compact counts such as 0/4 steps, and no left border.
- Completed tasks sort by actual completion time, newest first within the existing completion-day sections. App and widget completions share durable timestamps; undo removes the timestamp and recompleting moves the task to the top. Old records without an exact timestamp fall back to their recorded completion day and saved completion-key order.
- Within each priority section, Today, Upcoming and the widget sort tasks by scheduled time, then alphabetically for ties and untimed tasks.
- Priorities are High, Medium and Low, with a separate Priority not set section at the bottom. New tasks start unset. The down arrow is disabled at Low, the up arrow at High, while unset remains editable separately. A fresh click after a hold still moves one level. Legacy Highest becomes High and Lowest becomes Low; unset tasks keep their own section. Urgent tasks stay at the top of High before time/title sorting. Rounded 32px square up/down priority buttons sit immediately before each task gear, with matching button styling, centered arrows and the same arrow size as Do tomorrow. Hold up to jump to High or down to jump to Low, with native long-press haptics and no additional vibration permission. Moving away while still pressed cancels the hold; touch pointer-leave events after release do not cancel a normal tap. Releasing cannot apply a second change. Changes save to the task definition and carry forward to daily recurrences; limits are disabled.
- Buttons, inputs and menus use rounded rectangular corners; the main plus is a rounded square. App and Projects plus icons use rounded strokes painted with the app background or gradient over accent-colored buttons. The widget keeps a smaller bare accent-colored plus without a filled button or gradient, retaining a 48dp tap area and refreshing its color when the theme changes. Widget Quick Add uses the saved app colors, gradient direction, rounded panel and compact native controls with 8dp gaps between fields, side-by-side menus and buttons.
- Light haptics accompany app/Projects plus buttons, successful task creation, widget quick-add opening, and confirmed date/time selections. Feedback respects Android’s touch-feedback settings and needs no vibration permission.
- Widget Quick add supports several labels with checked selections, Today/Tomorrow/Weekend/custom dates and an optional time. After each successful add, title, labels, priority, date and time reset while the popup stays open.
- Quick add keeps its popup and keyboard ready after each saved task, clears the title, and pulses the entire white border twice without resizing the panel. This works in the app and home-screen popup. Scrollbars are hidden throughout the app and widget while touch scrolling remains available.
- The context dropdown chevron is inset 16px from the right edge.
- Horizontal swipes work across blank lower viewport space as well as task rows; dialogs and vertical scrolling retain their existing behavior.
- In-progress badges align with the title’s vertical center. In the app they sit immediately after the title with a 4px gap when there is room and stay below long titles; title checkboxes remain centered. Widget rows disable baseline alignment and extra font padding.
- Editable label emojis share the duration and repeat schedule row, wrapping only when necessary. One separator dot precedes the label section; individual labels have no separator dots. Schedule separators are slightly bolder with equal 6px spacing on each side.
- Repeating tasks have no Do today or Do tomorrow buttons in either tab; these day-move controls are available only for one-time tasks.
- Choose an unfinished task in the editor’s link dropdown to add it immediately to the selected chips. Save task persists the task and both sides of its links together. The task row shows a small 🔗 peer-title line immediately; links survive reloads and future daily recurrences. Cancel leaves saved links unchanged.
- Settings includes hex fields, swatches/color wheels, optional gradients, and a slate gradient preset. A separate viewport-sized background layer keeps the gradient visible while scrolling long lists in either tab; controls use translucent surfaces.
- The widget keeps completed rows checked for two seconds so a second checkbox tap can cancel completion. Pending requests are saved durably and recover on refresh or app resume.
- The interactive home widget is a native scrollable Today list with all open Today rows, no fixed row cap, no completed/history or upcoming rows, and a simple Today header without counts or list-name subtitles. Every row keeps its Today badge. With no open tasks, the widget centers its message against the full widget bounds with equal side margins and no extra font padding. It displays “You’re all done! Get some rest 🪻”, matching the app. Tap a task’s Today badge to start progress; it becomes a green rounded 🟢 IN PROGRESS badge matching the app and that row moves above the widget priority sections. Tap In progress to stop and restore the row’s normal priority/time/title position. There are no play/stop buttons. Progress stays shared with the app, but pinning affects only the widget; duplicate or stale taps do not toggle progress accidentally. Task titles use a slightly larger 13.5sp font. Quiet High/Medium/Low/Priority not set sections use faint dividers. The plus is aligned to the outer right edge without a button outline, tapping the Today header opens the app, and Android’s normal long-press widget menu opens configuration. There is no gear button or footer; small internal margins let content use nearly all available space. Context/checklist filters, colors and fully transparent 0% backgrounds remain configurable; its plus opens a small home-screen form. Existing widgets switch to the new layout on update.

Multiple tasks and checklist steps can be in progress together. The top banner joins their titles with commas; stopping or completing one preserves the others. Legacy single-task progress is migrated without changing task identities.

The app is called Tasks and uses the white icon with slate-gradient checklist lines and shapes, retaining rounded line ends. Windows development and pairing are deferred; this Android update requests no internet permission.

## Install

See [APK_BUILD.md](APK_BUILD.md) for the latest APK and [VALIDATION.md](VALIDATION.md) for verification. Requires Android 8.0 or newer. Install over the existing app; do not uninstall or clear its data.

## Build

Use JDK 21 and Android SDK Platform 35 / Build Tools 35.0.0:

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

GitHub Actions also checks the real packaged UI in Chromium. Release signing keys remain outside the repository; the downloadable personal-test APK uses the retained preview signing key for in-place updates.

See [CHANGELOG.md](CHANGELOG.md) for release changes.

For each release, add the newest entry to `app/src/main/assets/changelog.json`, mirror the history in `APP_CHANGELOG` in `bridge.js` and its packaged HTML copy, and update `CHANGELOG.md`. The browser checks require the Settings history to match the packaged history and current app version.
